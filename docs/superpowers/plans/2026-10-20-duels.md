# Duels + Kim bài (plan A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two players of a group duel asynchronously on lessons they both finished (round 1 timed multiple choice, round 2 oral), watch a replayed fight between their equipped heroes, and earn Kim bài, a currency only duels give.

**Architecture:** Server-authoritative duels (tables `duels`, `duel_runs`, RPCs `create_duel` / `submit_duel_run` / `list_duels`, lazy expiry, settlement in SQL). The app keeps its event-log wallet (ADR 0004): reading a settled duel appends a synced `duel_settled` event whose `kimBai` the wallet sums; the server credits its own computed reward once. Pure services mirror the SQL rules exactly. The catalogue gains a `currency` column now (with the three arena rows) so plan B only adds art and the Arena screen.

**Tech Stack:** Vite 5, React 18, TS strict, Tailwind 3.4 tokens, motion 11, Zustand 5, Zod 3, Dexie 4, Supabase JS 2 (Postgres 15 + pgTAP), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-duels-arena-design.md` (all sections; §7 only for the catalogue rows). Context: ADR 0004 (event log), ADR 0007 (boundaries), `docs/art-direction.md`, `docs/design-system.md`.

## Global Constraints

- No new dependency. TS strict (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`); no `any`, `enum`, `@ts-ignore`, no `x!` outside tests; imports via `@/`.
- Boundaries (ESLint): `features`/`ui` never import `adapters`/`content`; no feature→feature imports; `services` pure (no React/DOM/`Date.now`/`Math.random`); shared hooks `src/app/use*.ts` (`app-hook`); DI files are `src/app/{ServicesProvider.tsx,services.ts,appState.ts}`.
- UI strings only in `src/i18n/fr.ts` (French, tutoiement). Code/comments/commits in English. Tokens only; gold = earned rewards; one primary action per screen. UI tasks load `vietlearn-design`.
- **Duel rules (app = server, exact):** HP 100 each. Round 1 (multiple choice: `translate_choose`, `listen_choose`, `tone_pick`) 4–8 questions, target 8; round 2 (`speak`) 1–3, target 3. Round-1 hit 10; critical 15 when correct and `300 <= ms < 3000`; a correct answer with `ms < 300` counts 10 (no critical); `ms > 20000` = miss. Round-2 hit 15; `ms` not used. Damage = sum. `timeMs` = sum of round-1 `ms`, each capped at 20000. Winner: higher damage, then lower `timeMs`, else draw (`winner = null`).
- **Rewards (Kim bài):** win 3, draw 2, loss 1; forfeit win 3, forfeit absentee 0; cancelled (nobody played) 0.
- **Duel lifecycle:** expires 72 h after creation; expired with one run → settled, that player wins by forfeit; with none → `cancelled`. One `open` duel per pair; max 5 duels created per Paris day per challenger. Prerequisite for both players: `l01` in `lessons_done` and `d01` in `dialogues_done`; all `lessonId`s in the intersection of both players' `lessons_done`; same group; not oneself.
- **Event:** `duel_settled` — `refId` = duel id, `xp` 0, `payload { kimBai: number }`; synced; the wallet counts each `refId` once; the server credits `duel_runs.reward` once (`claimed`).
- **Catalogue:** `currency` = `"xu"` (all existing items) or `"kim_bai"`; new arena rows (theme `arene`): `hat_tay_son` hat 6, `acc_con_vo` accessory 8, `outfit_hoi_vat` outfit 10 — all `kim_bai`. Purchase in `kim_bai` debits Kim bài (refused without effect if short).
- RPCs never `raise` for a business rule: they return `{ ok: false, error: "<code>" }`. Only `not_authenticated` may raise. Security definer, `search_path` fixed, `auth.uid()` everywhere, execute granted to `authenticated` only. Triggers never raise.
- Never edit applied migrations. Never push to production (the controller does). **Commits: Marc only; never `Co-Authored-By`, never a Claude/AI mention.** `npm run lint` and `npm run verify` green before DONE.

## Review Focus

1. **Peeking**: the opponent's run (score, answers) must never reach a client before the duel is settled — `list_duels` and the fake both enforce it. Pinned in Task 1 pgTAP and Task 3 fake tests.
2. **Double crediting**: two devices or a retry append `duel_settled` twice → Kim bài counted once in the app and once on the server. Pinned in Task 2 and Task 1.
3. **Closing the app mid-duel**: on return, the displayed question counts as missed and the run resumes at the next one; the timer cannot be reset by reloading. Pinned in Task 4.
4. **Submitting offline**: the finished run is kept and sent automatically later; the screen says so; nothing is lost on reload. Pinned in Task 4.
5. **No speech recognition / mic lost**: cannot start (clear message); mic lost during round 2 → remaining oral questions missed, run still submits. Pinned in Task 4.
