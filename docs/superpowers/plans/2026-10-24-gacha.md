# Gacha « Xin xăm » Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace direct purchases of xu cosmetics with a per-theme gacha (rarities, guarantees, duplicates refunded in xu), drawn server-side and revealed with a « Xin xăm » pagoda-sticks animation.

**Architecture:** Server-authoritative pulls (RPC `gacha_pull`, idempotent on a client `pullId`, pure SQL rules fed by `random()` rolls) write coins/inventory/pity directly; the app mirrors each pull in its event log with a synced `gacha_pulled` event (the trigger only marks the pull claimed), recovers unclaimed pulls on start/online, and checks `min(local, server)` balance before pulling. The same rules exist as a pure TS service fed by injected rolls, tested on the same cases as pgTAP.

**Tech Stack:** Vite 5, React 18, TS strict, Tailwind 3.4 tokens, motion 11, Zod 3, Supabase (Postgres 15 + pgTAP), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-gacha-design.md` (approved 2026-10-21). Art: `docs/art-direction.md`; design: `docs/design-system.md`, `docs/superpowers/specs/2026-10-20-design-polish-audit.md` §D (perf guardrails).

## Global Constraints

- No new dependency. TS strict; no `any`/`enum`/`@ts-ignore`; `@/` imports; ESLint boundaries (features/ui never import adapters/content; no feature→feature; app-hooks never import features; services pure).
- UI strings in `src/i18n/fr.ts` (French, tutoiement, ` ` before `? ! : ;`); Vietnamese words `lang="vi"`. Tokens only; gold = earned rewards (legendary is gold). UI tasks load `vietlearn-design`.
- **Rarities (exact):** `common` 60 %, `rare` 28 %, `epic` 10 %, `legendary` 2 %. Duplicate refund: common 8, rare 20, epic 50, legendary 120 xu. Stick/seal colours: wood, jade, vermilion lacquer, gold.
- **Prices (exact):** 1 pull 40 xu; 10 pulls 360 xu.
- **Guarantees (exact):** pity counter per player and per theme advances by 1 per item drawn; the 40th item without a legendary is forced legendary, then the counter resets (any legendary resets it). In a ×10, if the first 9 items are all common, the 10th is forced at least rare. A complete set can still be pulled: every item is then a duplicate refunded in xu.
- **Draw algorithm (exact, same in SQL and TS):** for each item: if pity reaches 40 → legendary; else pick rarity from the roll `r ∈ [0,1)` with cumulative thresholds 0.60 / 0.88 / 0.98; apply the ×10 rule on the 10th item; then pick the item uniformly among the theme's items of that rarity with a second roll (if a rarity has no item in the theme, step down to the next lower rarity that has items). Duplicate = item already in the inventory (whatever its origin) or drawn earlier in the same pull.
- **Catalogue:** `shop_item` gains `rarity` (`common|rare|epic|legendary|null`). Gacha items = xu cosmetics with a `theme` and a `rarity` and `price = null` (never directly purchasable). Launch theme `legendes_sombres` (12 items: 4 common, 4 rare, 3 epic, 1 legendary): existing `hat_thuy_tinh` rare, `aura_waves` rare, `outfit_son_tinh` epic, `acc_thuan_thien` epic, `char_kiem_khach` epic, `char_phap_su` legendary; new `acc_giao_tre` « Lance de bambou » common, `hat_khan_vanh` « Turban de l'éclaireur » common, `outfit_ao_chen` « Tunique de rizière » common, `aura_suong_mu` « Brume du fleuve » common, `acc_quat_sat` « Éventail de fer » rare, `hat_mu_chien` « Casque de guerrier » rare. Arena (`kim_bai`) items and consumables unchanged; frames/fx unchanged.
- **Server:** RPCs security definer, `search_path` fixed, `auth.uid()`, granted to `authenticated` only, never `raise` for a business rule (return `{ ok:false, error }`); tables RPC-only (RLS on, `revoke all`). Migration `20261025000000_gacha.sql`, `set lock_timeout = '10s'` first; never edit applied migrations.
- **Event:** `gacha_pulled` — `refId` = pull id, `xp` 0, payload `{ theme, cost, items: [{ itemId, rarity, duplicate, refund }] }`; synced; counted once per `refId` by the wallet; the server trigger only sets `gacha_pulls.claimed = true` (never re-applies coins/inventory).
- **Perf (audit §D):** transform/opacity only; no blur/filter animation; ≤ 8 animated elements, ≤ 12 particles per SVG; no infinite loop off-screen; « Passer » always visible; reduced motion → result directly.
- **Shell safety (incident 2026-10-21):** the repo path contains a space — always quote paths/variables (`mkdir -p "$S"`), never `rm -rf` outside the repo or `.superpowers/`, `ls` a target before deleting.
- **Commits: Marc only; never `Co-Authored-By`, never a Claude/AI mention.** `npm run lint && npm run verify` (and `npm run test:e2e` for flow tasks) green before DONE.

## Review Focus

1. A lost response or a killed app during a pull never loses xu nor items (idempotent `pullId`, recovery of unclaimed pulls).
2. Fresh device / reinstall: pulling uses `min(local, server)`; recovered pulls appear once.
3. Old clients (1.5.x) still running after deploy: they cannot buy gacha items (server refuses: price null) and do not crash on `rarity` in the catalogue.
4. Complete set: pulling still works and refunds everything in xu.
5. Reduced motion / « Passer » / « Tout révéler »: results unchanged, reveal immediate.
